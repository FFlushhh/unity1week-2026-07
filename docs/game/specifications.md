# Game Specifications

## 状態

企画メモ反映済み・一部未決定。

この文書では、実装者とレビュアーが「仕様か不具合か」を判断できる粒度で記載します。
未決定の項目は推測で埋めず、`未決定`と記載します。

状態の意味:

- `確定`: 企画メモで明示され、MVPの前提として扱う
- `草案`: 企画メモに案として記載されているが、実装前の合意が必要
- `未決定`: 実装方法または期待動作を決める必要がある

`確定`、`草案`、`未決定`は仕様の確定度を表す。
機能の実装優先度は、後述するMoSCoW分類で管理する。

## 一文で説明

動く被写体をタイミングよく自撮り写真へ収め、架空のSNSで多くの「いいね」を
獲得する2Dスコアゲーム。

## コア体験

10秒間に背景を横切る被写体の予兆と動きを見て、加点対象を写真へ収め、
減点対象を避けるタイミング判断を楽しむ。

## ゲーム進行

```text
タイトル
→ 難易度選択（Could）
→ 撮影開始メッセージ
→ 10秒間の写真撮影
→ 架空SNSへ投稿
→ いいね・コメント表示
→ 次の時間帯へ
→ 全時間帯終了後にリザルト
→ タイトルへ戻る
```

- 難易度選択はCouldとし、Mustのみで完成させる場合は省略する。
- 時間帯の数と各時間帯の内容は未決定。
- 写真ごとのSNS表示と、全写真終了後の最終リザルトは別の画面状態として扱う。
- 各画面を別シーンにするか、1シーン内の状態切り替えにするかは未決定。

### 開始

1. タイトルを表示する。
2. プレイヤーの操作でゲームを開始する。
3. 難易度選択を採用する場合は、選択後に最初の時間帯を開始する。

タイトルの具体的な表示内容と開始入力は未決定。

### 撮影

1. 撮影場所を示すメッセージを表示する。
2. 撮影可能時間を10秒間とする。
3. 撮影中、得点対象または減点対象のオブジェクトが背景を移動する。
4. プレイヤーがシャッターを切ると、その時点で写真枠内にいる対象を記録する。
5. 撮影結果を架空SNSの投稿として表示する。
6. 投稿についた「いいね」とコメントを表示し、次の時間帯へ進む。

1つの時間帯で撮影できる枚数、時間切れ時の挙動、撮影後に残り時間を止めるかは未決定。

### 終了

全時間帯の撮影終了後、獲得した「いいね」に応じたリザルトを表示する。

リザルトでは、撮影した写真、合計スコア、主人公の表情を表示する想定。
表示対象と表情の切り替え条件は未決定。

### リトライ

リザルト後はタイトルへ戻る。
リザルトから直接リトライできるようにするかは未決定。

## 撮影判定

### 判定方法

各得点対象オブジェクトには、写真へ写ったかを判定する基準点を1つ設定する。
撮影時点で基準点が写真枠内にあれば、そのオブジェクトを撮影対象として記録する。

例として、猫は顔の位置を基準点にする。

次の境界条件は未決定:

- 基準点が枠線上にある場合
- 非表示、退場中、または他のオブジェクトに隠れている場合
- 同じオブジェクトを複数回撮影できる場合の重複計上
- 主人公や障害物に隠れた減点対象を計上するか

### 写真データ

撮影画像には`RenderTexture`と`Texture2D`を使用する。

1. 撮影用Cameraの出力先を`RenderTexture`にする。
2. 撮影中は`RenderTexture`をプレビューとして表示する。
3. シャッター時に`RenderTexture`の内容を`Texture2D`へコピーする。
4. `Texture2D`に、撮影対象の種類と個数を関連付けて保持する。
5. SNS画面とリザルトでは、保持した`Texture2D`をUIの`RawImage`へ表示する。

画面全体を撮影する`ScreenCapture`は使用せず、カメラUIを撮影画像に含めない。
再撮影やリトライで不要になった`Texture2D`は破棄し、プレイを繰り返したときに
画像データがメモリへ残り続けないようにする。

## スコア

- 写真に写った対象の種類と個数から写真ごとの基礎点を計算する。
- 加点対象は正の点、減点対象は負の点を持つ。
- 架空SNSについた「いいね」の数をプレイヤーへ表示するスコアとする。
- 全写真のスコアをどのように合算するかは未決定。
- 基礎点から「いいね」数への変換方法は未決定。
- 0未満のスコアを許可するかは未決定。
- コメントは演出として表示する想定だが、スコアへの影響は未決定。

暫定的な計算モデル:

```text
写真の基礎点 = Σ（写った対象の個数 × 対象ごとの点数）
```

対象ごとの具体的な点数は未決定。

## 被写体・障害物

すべて2Dで表現する。奥行きは、オブジェクトごとに設定したスケールと移動速度で
遠近感を表現し、登場後は原則としてそのスケールと速度を維持して横切る。

企画メモにある候補:

| 対象 | 得点傾向 | 予兆・特徴 | 状態 |
|---|---|---|---|
| 犬 | 加点 | 毎回同じタイミングで出現 | 草案 |
| 猫 | 加点 | 犬より速く、毎回同じタイミングで出現 | 草案 |
| スズメ | 小幅な加点または減点 | 電線の揺れ、羽 | 得点方向が未決定 |
| 孔雀・青い鳥 | 大幅な加点 | 電線の揺れ、羽 | 草案 |
| 桃 | 加点 | 川の音。低確率で出現 | 草案 |
| 汚れた服の人 | 大幅な減点 | 音が鳴り、移動が遅い | 草案 |
| 狂犬 | 大幅な減点 | 吠える音 | 草案 |
| ビニール袋・傘 | 減点 | 強風や音。複数出現する場合がある | 低優先度の草案 |
| 手ぶれ | 減点 | 強風時に一定確率で発生 | 低優先度の草案 |
| 川のゴミ | 小幅な減点 | 川の音。複数出現する場合がある | 草案 |

MVPへ採用する対象と最低種類数は未決定。

難易度選択はCouldとし、Mustの完成後に時間がある場合だけ実装する。

実装する場合の難易度数と、出現対象、速度、予兆、制限時間、スコアのうち

## UI

### タイトル

- タイトルを表示する。
- ゲーム開始の導線を表示する。
- 難易度選択を採用する場合は、その導線を表示する。

具体的なレイアウトと入力案内は未決定。

### 撮影中

- スマートフォンのカメラを想起させる、簡素なオリジナルUIを使用する。
- 写真枠を表示する。
- 残り時間をプレイヤーが確認できるようにする。
- シャッター操作を表示する。

残り時間の表示形式と、撮影済み対象の得点を撮影中に見せるかは未決定。

### SNS表示

- 実在サービスのロゴや画面を複写せず、架空SNSのオリジナルUIとする。
- 撮影した写真を投稿として表示する。
- 「いいね」とコメントが増える様子を表示する。
- 次の時間帯へ進む導線を表示する。

コメントの文面、件数、対象別の対応は未決定。

### リザルト

- 撮影結果とスコアを表示する。
- 主人公の嬉しい表情または悲しい表情を表示する。
- タイトルへ戻る導線を表示する。

表情の切り替え基準は未決定。

## MoSCoW

この分類は、2026年8月2日の公開版に対する実装優先度を表す。
まずMustだけでゲームを1周遊べる状態にし、完成を確認してからShould、Couldの順に着手する。

### Must

ゲームとして成立し、公開可能な最小範囲。
1つでも未完成ならShouldとCouldへ着手しない。

- タイトルからゲームを開始できる
- 撮影場所を示すメッセージを表示できる
- 10秒間、被写体が背景を移動する
- `RenderTexture`から`Texture2D`へ写真を撮影できる
- 写真枠内の対象と個数を判定できる
- 対象と個数からスコアを計算できる
- 撮影結果を保持し、SNS表示で確認できる
- 「いいね」とコメントを表示できる
- 複数の時間帯を順に進行できる
- 全時間帯の終了後にリザルトを表示できる
- タイトルへ戻り、もう一度プレイできる
- 進行に必要な最低限のボタンUIがある
- 主人公、得点対象、カメラ、SNS、リザルトに最低限必要な画像がある

### Should

なくてもゲームは成立するが、撮影結果の理解しやすさや手応えを高める機能。

- シャッターを切ったときの演出
- 「いいね」とコメントが増える演出
- 加点または減点対象の出現を知らせる予兆SE
- スコアに応じた主人公のリザルト表情切り替え

### Could

MustとShouldの完成後、時間に余裕がある場合だけ実装する機能。

- 難易度選択
- ランダム出現またはレア被写体の追加
- スコアに応じた収入
- アクセサリーの購入と装着
- アクセサリーが写真に写った場合の効果

収入、ショップ、アクセサリーは相互に依存するため、一部だけを先行実装しない。

### Won't

今回の公開版では実装しない。

- 実在SNSとの連携
- オンラインランキング
- 実在SNSのロゴや画面の複写
- 写真フィルターや画像加工機能

## エッジケース

実装前に期待動作を決め、テストまたはPlay Modeで確認する。

- 制限時間とシャッター入力が同じフレームに発生した場合
- 制限時間内に撮影しなかった場合
- シャッターを連打した場合
- 写真枠内に対象が1つもない場合
- 同じ種類の対象が複数写った場合
- 加点対象と減点対象が同時に写った場合
- 合計点が0または負になった場合
- 基準点が写真枠の境界上にある場合
- 撮影と対象の生成・退場が同じフレームに発生した場合
- SNS表示やシーン遷移中に入力した場合
- リトライ後に前回の写真、スコア、タイマーが残らないこと
- 必須のInspector参照が未設定の場合
- `Time.timeScale`を変更する演出を採用した場合のタイマー動作
