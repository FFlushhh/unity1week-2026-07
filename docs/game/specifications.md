## 一文で説明

動く被写体をタイミングよく自撮り写真へ収め、架空のSNSで多くの「いいね」を
獲得する2Dスコアゲーム。

## コア体験

10秒間に背景を横切る被写体の予兆と動きを見て、加点対象を写真へ収め、
減点対象を避けるタイミング判断を楽しむ。

## ゲーム進行

MVPのゲーム進行:

```text
タイトル
→ 撮影開始メッセージ
→ 10秒間の写真撮影
├─ 10秒以内に撮影できた
│  → カウントダウン終了
│  → ResultScene内のSNS風投稿・リザルト演出
│  → タイトルへ戻る
└─ 撮影できずに時間切れ
   → Gameシーン内のゲームオーバーUI
   → タイトルへ戻る
```

- MVPでは1ステージにつき写真を1枚だけ撮影し、その写真のリザルトを表示する。
- 本編案では3ステージで3枚撮影する。各ステージで「10秒間の写真撮影、
  カウントダウン終了、架空SNSへの投稿演出」を順に行い、投稿演出の終了後は
  次のステージの撮影を開始する。最後のステージの投稿演出後に、写真ごとの結果を
  順番に表示し、最後に合計リザルトを表示する。ただし、3ステージ化はMVPに含めない。
- 難易度選択はCouldとし、Mustのみで完成させる場合は省略する。
- MVPのシーン構成は`Title`、`Game_Stage1`、`ResultScene`とする。SNS風投稿とリザルトは
  `ResultScene`内で連続して表示する。Gameはステージごとに別シーンを作成できる構成とし、
  MVPでは`Game_Stage1`だけを使用する。
- MVPのGameOverは、Gameシーン内のUIとして表示する。

本編案（Could）のゲーム進行:

```text
タイトル
→ ステージ1: 撮影開始メッセージ → 10秒間の写真撮影 → カウントダウン終了 → SNS投稿演出
→ ステージ2: 撮影開始メッセージ → 10秒間の写真撮影 → カウントダウン終了 → SNS投稿演出
→ ステージ3: 撮影開始メッセージ → 10秒間の写真撮影 → カウントダウン終了 → SNS投稿演出
→ 写真ごとのリザルトを順番に表示
→ 合計リザルト
→ タイトルへ戻る
```

### 開始

1. タイトルを表示する。
2. GUIボタンのクリック、Spaceキー、またはEnterキーでゲームを開始する。
3. 難易度選択を採用する場合は、選択後に最初のステージを開始する。

タイトルの具体的なレイアウトは未決定。

### 撮影

1. 撮影場所を示すメッセージを表示する。この間、カメラ映像にはピント合わせ演出を適用する
   （詳細は「演出」の「ピント合わせ演出」を参照）。
2. 撮影可能時間を10秒間とする。
3. 撮影中、得点対象または減点対象のオブジェクトが背景を移動する。
4. プレイヤーは1回だけシャッターを切れる。
5. シャッター時点で写真枠内にいる対象を記録する。
6. 撮影後も10秒のカウントダウン終了までタイマーと被写体を動かし続ける。
7. 10秒以内に撮影できなかった場合はゲームオーバーとする。
8. 撮影できた場合は、カウントダウン終了後に`ResultScene`へ遷移し、SNS風投稿と
   リザルトの演出を自動再生する。

### 終了

MVPでは`ResultScene`内でSNS風投稿の表示に続けて、撮影した1枚の写真、いいね数、
コメント、主人公の表情をリザルトに表示する。

本編案では写真ごとの結果を操作で順番に表示し、全写真の表示後に合計値を表示する。
主人公の表情は良い・普通・悪いの3段階とするが、境界値はプレイ確認後に決める。

### リトライ

リザルト後はタイトルへ戻る。
ゲームオーバー後の遷移と、リザルトから直接リトライできるようにするかは未決定。

## 撮影判定

### 判定方法

各得点対象オブジェクトには、写真へ写ったかを判定する判断ポイントを1つ設定する。
判断ポイントは被写体の子に置く空のGameObject（`Transform`）とする。
撮影時点で判断ポイントが写真枠内にあり、かつ判断ポイントが他の描画物に隠れて
いなければ、そのオブジェクトを撮影対象として記録する。

判断ポイントは被写体ごとに、見た目として意味のある位置へ置く。

| 被写体 | 判断ポイントの位置 |
|---|---|
| 犬 | 顔中央 |
| 汚れた服の人 | 顔中央 |
| 狂犬 | 顔中央 |
| ビニール袋 | 袋本体の中央 |
| 鳥 | 胴体中央 |
| スズメ | 胴体中央 |
| 自撮り | 顔中央 |

- 基準点が枠線上にある場合は枠内として扱わない。
- 他の描画物により判断ポイントが隠れている対象は、写真枠内でも撮影対象として扱わない。
- MVPでは1ステージにつき撮影は1回だけなので、同じオブジェクトの重複撮影は発生しない。
- 隠れ判定は、判断ポイントの位置にある`PhotoSubject`レイヤーの`Collider2D`のうち、
  対象より前面に描画されるものを調べて行う。前後関係は対象の`SpriteRenderer`の
  `Sorting Layer`、次に`Order in Layer`で比較する。
- 被写体同士が見た目として重なっていても、前面Colliderが判断ポイントを覆わなければ
  撮影対象とする。被写体が写真枠をまたいでいても、判断ポイントが厳密に枠内なら
  撮影対象になり得る。
- `Collider2D`は見た目の不透明部分の近似とする。現在の7被写体（犬、汚れた服の人、狂犬、
  ビニール袋、鳥、スズメ、自撮り）はすべて`PolygonCollider2D`を使用する。このため、
  透明部分や複雑な輪郭ではピクセル単位の表示結果とは一致しない。
- Colliderは主要な不透明輪郭だけを近似し、小さな突起、毛先、アンチエイリアス、装飾は
  追わない。判断ポイントは必ず自身のCollider内へ収める。
- 離れた不透明部分は複数パスで表現し、透明領域を塞がない。汚れた服の人は頭胴体・左右腕・
  左右脚を、ビニール袋は本体・左右の持ち手をそれぞれ別パスにする。持ち手の穴はPolygonの
  「穴」ではなく、離れたパスの組み合わせで表現する。
- 左右反転時は`SpriteRenderer.flipX`に加えて、判断ポイントの`localPosition.x`と
  `PolygonCollider2D`の全頂点・オフセットのXも反転する。これにより、反転して出現した
  被写体でも見た目と判定が一致する。PathAnchor（足元アンカー）は反転しない。
- 重なり得る被写体には一意な`Order in Layer`を設定する。同じ描画優先度で重なった場合は
  遮蔽とみなさないが、表示結果と判定が一致しない可能性があるため設定で回避する。
- `PhotoSubject`レイヤー上でColliderだけ、または`SpriteRenderer`／`StageSubject`参照が
  不足しているオブジェクトは設定不備としてWarningを出す。RendererがないColliderは
  安全側に倒して遮蔽物として扱う。

### 写真データ

撮影画像には`RenderTexture`と`Texture2D`を使用する。

1. 撮影用Cameraの出力先を`RenderTexture`にする。
2. 撮影中は`RenderTexture`をプレビューとして表示する。
3. シャッター時に`RenderTexture`の内容を`Texture2D`へコピーする。
4. `Texture2D`に、撮影対象の種類と個数を関連付けて保持する。
5. `ResultScene`では、保持した`Texture2D`をSNS風投稿の写真枠にあるUIの`RawImage`へ表示する。

ランダムピンボケが発生中に撮影した場合は、その時点のぼかし強度を`Texture2D`へ焼き込む。
カメラUI、タイマー、シャッターは撮影画像に含めない。ピンボケ開始から1.0秒以上2.0秒以下の
シャッターは、被写体判定の結果にかかわらずスコアを0へ強制する。

隠れ判定や枠内判定は、得点・被写体IDごとの集計に使う一覧だけへ適用する。
撮影画像はPhotoCameraの`RenderTexture`をそのままコピーし、得点対象外、隠れた被写体、
または写真枠をまたぐ被写体も非表示にせず通常どおり記録する。

画面全体を撮影する`ScreenCapture`は使用せず、カメラUIを撮影画像に含めない。
`Texture2D`の所有権は、撮影後はStageの`StagePhotoCaptureController`、Result遷移時は
`ResultDataTransporter`を経由したResult、Result表示後は`ResultSceneManager`が持つ。
所有権をResultへ移譲した後はStageは破棄せず、ResultSceneの破棄時にResultが1回だけ破棄する。
遷移準備やロードに失敗した場合は、移譲しようとした画像を破棄して残留させない。

## スコア

- 写真は固定値1,000いいねから開始する。
- 写真に写った対象の種類と個数から加減点を計算する。
- 加減点といいね数の変換比率は1:1とする。
- 計算結果が0以下の場合、表示するいいね数は0とする。
- MVPは写真1枚なので、その写真のいいね数を最終結果とする。
- コメントは演出だけに使用し、スコアへ影響させない。
- ピンボケの0点区間で撮影した写真は、基礎点と被写体別加減点にかかわらず0いいねとする。
- 強制0点の写真では、基礎点と被写体別の明細を表示せず、明細には`ピンボケ`の0点だけを表示する。
  合計、ランク、投稿文、unityroomへ送信する値は0点として扱う。

スコア計算の正本はResult Featureとする。Stageは隠れ判定を適用済みの被写体IDごとの個数と
撮影画像を`ResultData`へ渡すだけで、対象ごとの点数、加減点、合計、0への丸めを計算しない。
`ResultSceneManager`と`ResultScoreCalculator`が、Result Featureの点数マスターを使用して
最終的ないいね数を計算する。

```text
加減点 = Σ（写った対象の個数 × 対象ごとの点数）
写真のいいね数 = max(0, 1,000 + 加減点)
```

内部の加減点が負になることは許可するが、プレイヤーへ表示するいいね数は負にしない。
本編案の3枚分を合算する方法は、3ステージ化へ着手する前に決める。

Result Featureの点数マスターは、Stageが渡す表示名と一致させる。

| Result表示名 | 点数 |
|---|---:|
| 犬 | +500 |
| 汚れた服の人 | -600 |
| 狂犬 | -800 |
| ビニール袋 | -100 |
| 鳥 | +800 |
| スズメ | +5 |
| 自撮り | +1,000 |

リザルトのランクは合計いいね数で決め、境界はS: 10,000以上、A: 8,000以上、B: それ未満とする。

### unityroomスコアボードへの送信

確定した合計いいね数は、リザルト演出確定時（`ResultSceneManager.FinishSequence()`）に
unityroomのスコアボードへ`UnityroomScoreSubmitter`経由で非同期送信する。送信はWebGL
ビルド時のみ行い、Unity Editor実行時は送信をスキップする。送信の成否はゲーム進行
（次シーンへの遷移操作）に影響させない。詳細は`ADR-0017`を参照。

## 被写体・障害物

すべて2Dで表現する。奥行きは、オブジェクトごとに設定したスケールと移動速度で
遠近感を表現し、登場後は原則としてそのスケールと速度を維持して横切る。

MVP候補のうち、採用と点数が確定している対象:

| 対象 | 点数 | 予兆・特徴 | 状態 |
|---|---:|---|---|
| 犬 | +500 | 10秒間の決められた時刻と速度で出現する | 確定 |
| 汚れた服の人 | -600 | 音が鳴り、移動が遅い | 確定 |
| 狂犬 | -800 | 吠える音 | 確定 |
| ビニール袋 | -100 | 強風や音。複数出現する場合がある | 確定 |
| 鳥 | +800 | 未決定 | 確定 |
| スズメ | +5 | 未決定 | 確定 |
| 自撮り（主人公） | +1,000 | 移動せず、PhotoCameraの左下へ固定表示する | 確定 |

### 自撮り被写体

主人公は撮影される側の被写体としても扱い、写真に写れば加点する。

| 項目 | 内容 |
|---|---|
| ID | `SubjectId.SelfieGirl`（列挙値6） |
| 点数 | +1,000いいね |
| Result表示名 | 自撮り |
| 使用画像 | `Assets/Images/Girl/自撮り1.png` |
| 配置 | `Game_Stage1`の`StageRoot/FixedSubjectRoot`直下へ1体だけ固定配置する |
| 判断ポイント | 顔中央 |
| Sorting Order | 100 |
| 移動 | `SubjectMover`を持たず、出現タイムラインにも登録しない |

- 自撮りはSorting Order 100で、移動被写体（10〜60）より常に前面へ描画する。
  このため前景として既存被写体を遮蔽し、自身は既存被写体に遮蔽されない。
- PhotoCameraの表示領域の左下へ寄せ、不透明部分が横幅の約半分、高さの約4分の3を占める
  大きさで配置する。判断ポイントは常にPhotoCameraの厳密な内側に入る。
- 配置は透明余白を含むSpriteのBoundsではなく、不透明部分を近似したColliderのBoundsを
  基準に決める。
- `自撮り0.png`は本編で使用しない予備イラストとする。

### Stage1の出現タイムライン

出現時刻は`Game_Stage1`有効化後の経過秒数とし、`StartMessage`中から通常スケジュールの
生成を開始する。最初の`Playing`開始時にもスケジュールを作り直さず、すでに生成した被写体と
残りの生成予定を維持する。犬は0.3秒・速度4.0を固定し、出現する左右だけをプレイごとに50%で
決める。犬以外も時刻、個数、ルート、左右を`Game_Stage1`有効化時にランダム生成し、そのプレイ中は
同じスケジュールを保持する。リトライ時は新しいスケジュールを生成する。

`Game_Stage1`の有効化直後には、通常スケジュールとは別に6種類から重複なしで2〜3体を選び、
PhotoCamera内のX=-5.0〜5.0へランダムに配置する。初期配置した被写体は`StartMessage`中から
移動を開始し、`Playing`開始時には破棄しない。初期配置は流動的な演出として扱うため、
`Playing`開始前に画面外へ退場することを許可する。

通常スケジュールの初回バッチでは、犬を含めて毎回8〜12体を生成する。別種類との時刻重複は
許可し、同種類の生成間隔は0.25秒以上とする。バッチ内のすべての生成後は、犬を再生成せず、
ランダム被写体だけで次のバッチを作成する。`GameOver`になるまでこの処理を繰り返し、
`Completed`中もシーン退出までは生成と移動を継続する。

| 被写体 | 出現数 | 出現秒 | 基準出現X | 方向 | 速度 | Y配置 | 動作 |
|---|---:|---|---:|---|---:|---|---|
| 犬 | 1（固定） | 0.3 | -9.5 | 基準は左から右、左右を50%で反転 | 4.0 | FootPoint=-4.4 | 直線移動 |
| 汚れた服の人 | 1〜2 | 0.5〜3.0のランダム | -9.5 | 基準は左から右、左右を50%で反転 | 3.0 | FootPoint=-4.4 | 地上被写体中で最も遅い直線移動 |
| 狂犬 | 1〜2 | 0.7〜3.8のランダム | 9.5 | 基準は右から左、左右を50%で反転 | 5.5 | FootPoint=-4.4 | 高速の直線移動 |
| ビニール袋 | 2〜3 | 0.4〜4.8のランダム | ルートごと | 基準方向を左右50%で反転 | ルートごと | ルートごと | ルートごとの上下揺れ |
| 鳥 | 1〜2 | 0.8〜4.5のランダム | 9.5 | 基準は右から左、左右を50%で反転 | 4.5 | Y=2.0 | 直線移動 |
| スズメ | 2（固定） | 1.2〜5.0のランダム | -9.5 | 基準は左から右、左右を50%で反転 | 5.0 | Y=1.0 | 直線移動 |

左右を反転する場合は、基準出現Xの符号と進行方向をともに反転する。Prefabの回転と縮尺は
変更せず、見た目は`SpriteRenderer.flipX`で反転する。判断ポイントと`PolygonCollider2D`も
X座標を反転し、見た目と撮影判定を一致させる。足元アンカー（FootPoint／PathAnchor）は
反転しない。これにより、既存の見た目と進行方向の関係を反対側の出現でも維持する。

ビニール袋のルートは、1個ごとに以下のどちらかを独立して等確率で選ぶ。同じルートの連続は
許可する。各ルートも左右を50%で反転する。

| 基準ルート | 出現X | 方向 | 速度 | Y配置 | 動作 |
|---|---:|---|---:|---|---|
| 低空 | -9.5 | 左から右 | 4.0 | Y=-2.5 | 振幅0.35、周波数1.2Hzの上下揺れ |
| 高空 | 9.5 | 右から左 | 4.5 | Y=-1.6 | 振幅0.35、周波数1.2Hzの上下揺れ |

写真判定点がPhotoCameraの撮影範囲の進行方向奥側へ、10秒の制限時間までに到達できる
出現上限と速度を設定する。出現時刻、速度、出現位置をInspectorで変更するときも、この条件を
満たす値にする。犬、汚れた服の人、狂犬はSceneの`Spawn Position Y`を-4.4、
`Use Path Anchor For Spawn Position`を有効にし、Prefabに置く`FootPoint`を地面レーンへ合わせる。
これにより、Spriteの中心位置や大きさではなく足元を背景の歩行可能な前景へ揃える。
ビニール袋、鳥、スズメは空中被写体として表のY位置へ配置する。
被写体固有の予兆SEとスズメ用画像の差し替えは、素材が未確定のため今回の範囲に含めない。

桃は+4,000いいねの被写体候補であり、川がある本編ステージだけに出現する。MVPには含めない。

猫、孔雀・青い鳥、手ぶれ、川のゴミなど、上表にない企画候補はMVP外とする。

## 難易度

難易度選択はCouldとし、Mustの完成後に時間がある場合だけ実装する。

実装する場合の難易度数と、出現対象、速度、予兆、制限時間、スコアのうち
何を変化させるかは未決定。

## ゲームクリア・ゲームオーバー条件

- 10秒以内に1枚も撮影できなかった場合はゲームオーバーとする。
- 10秒以内に撮影できれば、いいね数にかかわらずリザルトへ進む。
- スコアによるゲームオーバーは設けず、ゲームを完了した後はスコアアタックとして扱う。
- MVPのGameOverはGameシーン内のUIとして表示し、タイトルへ戻る。

## UI

### タイトル

- タイトルを表示する。
- ゲーム開始の導線を表示する。
- 難易度選択を採用する場合は、その導線を表示する。

具体的なレイアウトと入力案内は未決定。

### 撮影中

- Stage1は、1920×1080を基準にした横向きのオリジナルカメラUIを使用する。中央に縦幅最大の4:3カメラ領域を置き、左右同幅の黒帯へ操作部品を配置する。
- StandaloneおよびWebの初期起動解像度は1920×1080（16:9）とする。4:3の既定解像度では左右の操作帯を確保できないため、今回の対象外とする。
- PhotoCameraの4:3映像を`PhotoPreviewCanvas`中央のカメラ領域へ表示する。カメラUIと左右の黒帯は画面UIであり、撮影画像には含めない。
- MVPではカメラフレームを固定し、被写体はPhotoCamera映像の近傍で出現して4:3プレビューを横切る。
- `camera_ui_frame.png`は実行時UIへ配置せず、左右の黒帯と個別の操作部品でカメラUIを構成する。
- カメラ部品のうち操作できるのはシャッターだけとする。カメラ切替、写真・動画モード、ズーム、フラッシュ、Live Photo、比率、セルフタイマー、設定メニューは装飾表示のみとする。
- 写真・動画モードはPHOTO固定、ズーム表示は固定画像とし、ゲーム中に変更しない。
- シャッターは左側の円形ボタンとして表示する。撮影後は左上の円形サムネイルへ4:3画像を中央クロップして表示し、カメラ切替は左下へ表示する。
- 残り時間は白文字・小数1桁で画面上中央へ表示する。開始メッセージ中はTimerを表示せず、Playing開始後から表示する。
- GameOver時はゲーム画面を黒へフェードアウトし、完全に暗転した後でGameOver UIを表示する。

撮影済み対象の得点を撮影中に見せるかは未決定。

### SNS表示

- 実在サービスのロゴや画面を複写せず、架空SNSのオリジナルUIとする。
- SNS風投稿とリザルトは、MVPでは同じ`ResultScene`内で連続して表示する。
- 10秒以内に撮影できた場合、カウントダウン終了後に`ResultScene`内の投稿・リザルト演出を
  自動再生する。
- 「いいね」とコメントが増える演出はShouldとする。
- 表示する最終いいね数が0の場合（通常の0点、負の計算結果を0表示した場合、ピンボケによる強制0点を含む）は、
  弾幕コメントだけを通常どおり流す。ハート、いいね増加SE、投稿パネルのバウンド、スコアカウントアップSEは再生しない。
  その代わりに、Game_Stage1のゲームオーバー時と同じSEをリザルトで1回再生する。

コメントの文面、件数、対象別の対応は未決定。

### リザルト

- MVPでは撮影した1枚の写真、いいね数、コメントを表示する。
- MVPでは主人公の表情を表示する。
- タイトルへ戻る導線を表示する。

Shouldでは良い・普通・悪いの3段階へ切り替える。境界値は、実際にプレイして
バランスを確認した後に決める。
本編案では、写真ごとの結果をクリックで順番に表示し、最後に合計値を表示する。

## 演出

MVP完成後、次の順に追加する。

1. iPhoneのカメラを参考にした、オリジナルのシャッター演出
2. コメントが現れる演出
3. 「いいね」の数字が強調されながら増える演出

### シャッター演出

- シャッター時は、撮影画像を確定したあとに、PhotoCamera映像の中央4:3プレビューだけを一時的に暗転する。
- カメラフレーム、Timer、シャッターなどのカメラUIは暗転させない。
- 暗転UIは画面UIとして表示し、PhotoCameraが保存する撮影画像には焼き込まない。
- 暗転から復帰したあと、撮影済み画像を左上の円形サムネイル内で、プレビューの中心位置を基準に拡大表示する。
- 演出中もタイマーと被写体の更新を継続する。残り時間が0秒になった時点で演出中の場合は、
  演出完了後に`ResultScene`へ遷移する。
- 初期時間は、暗転0.08秒、黒保持0.08秒、復帰0.08秒、写真拡大0.16秒（合計約0.4秒）とする。
  これらは初期値であり、Inspectorから調整可能とする。

### ピント合わせ演出

- `Game_Stage1`へ遷移した直後から、PhotoCamera映像の中央4:3プレビューだけにぼかしを適用する。
- カメラフレーム、Timer、シャッター、開始メッセージなどのカメラUIには、ぼかしを適用しない。
- ぼかしは画面UI側（プレビュー表示用のマテリアル）で表現し、PhotoCameraが保存する撮影画像や
  Resultへ渡す画像には焼き込まない。
- 被写体の生成・移動は、演出中も既存どおり進行する。
- 撮影タイムが開始するまで、シャッター入力と撮影タイマーは有効にしない。
- 撮影タイム開始までにぼかしを徐々に弱め、完全に解除する。解除後は短い待機時間を挟んでから
  撮影タイムを開始する。
- 初期時間は、ぼかし解除1.6秒、解除後の待機0.4秒（合計約2.0秒）とする。これらは初期値であり、
  Inspectorから調整可能とする。ぼかしの強さも同様にInspectorから調整可能とする。
- シーンの再読み込みや再プレイ時に、前回のぼかし状態や進行状態を残さない。

### ランダムピンボケ

- `Playing`開始後の10秒間、0.5秒ごとに独立抽選する。1ゲーム中に1回以上発生する確率は約20%とし、
  各抽選の当選確率は20区間全体でこの確率になる値を用いる。
- 当選した場合、該当する0.5秒区間内のランダムな時刻から3秒間ぼかす。撮影後も10秒の
  カウントダウン終了までは新規発生を許可する。
- 開始から1.5秒まで既存の`SmoothStep`で強くし、1.5秒をピークとして3秒まで同じ曲線で解除する。
- 重複するイベントは最大のぼかし強度を表示し、いずれかの0点区間に入っていれば0点とする。
- すべての重複ピンボケが解消して表示強度が0になったとき、ゲーム開始時のピンボケ解消と同じSEを鳴らす。
- 10秒終了後は新規発生しない。終了間際に始まった演出はResult遷移を待たせず、シーン破棄時に打ち切る。

## シーン

必要最小限のシーン数とし、機能は可能な範囲でPrefabへ分離する。

| 画面状態 | 用途 | シーン分割 |
|---|---|---|
| Title | タイトル・開始 | 分割する |
| Difficulty | 難易度選択 | 機能自体がCould |
| Game_Stage1 | 撮影 | ステージごとに分割可能。MVPではこの1シーン |
| ResultScene | SNS風投稿・写真・いいね・コメント表示 | MVPではSNSとリザルトを同一シーンで扱う |
| GameOver | 未撮影による失敗表示 | MVPではGame内UI |

Bootstrapは導入しない。
写真、スコア、進行状態はデータを渡す側が受け渡し処理を実装する。MVPではStageが
撮影画像と被写体IDごとの個数を`ResultData`としてResultへ渡し、Resultがスコアを計算する。
具体的なnull可否、Texture2Dの所有権、破棄タイミング、受け渡し失敗時の挙動は
`StagePhotoCaptureController`と`Stage1SceneTransitionController`の契約に従う。

詳細は`docs/decisions/ADR-0011-scene-and-bootstrap-policy.md`を参照する。

## MoSCoW

この分類は、公開版を遊びごたえのある状態へ仕上げるための実装優先度を表す。
MVPの1周動作を確認したため、現在はShouldを優先して実装する。CouldはShouldの完成後に着手する。

### Must

ゲームとして成立し、公開可能な最小範囲。
1つでも未完成ならShouldとCouldへ着手しない。

- タイトルからゲームを開始できる
- 撮影場所を示すメッセージを表示できる
- 10秒間、被写体が背景を移動する
- `RenderTexture`から`Texture2D`へ写真を撮影できる
- 写真枠内の対象と個数を判定できる
- 対象と個数からスコアを計算できる
- 撮影結果を保持し、SNS表示で確認できる
- 「いいね」とコメントを表示できる
- 10秒以内に未撮影の場合、ゲームオーバーを表示できる
- SNS投稿演出後に1枚分のリザルトを表示できる
- タイトルへ戻り、もう一度プレイできる
- 進行に必要な最低限のボタンUIがある
- 主人公、得点対象、カメラ、SNS、リザルトに最低限必要な画像がある

### Should

なくてもゲームは成立するが、撮影結果の理解しやすさや手応えを高める機能。

- シャッターを切ったときの演出
- 「いいね」とコメントが増える演出
- 加点または減点対象の出現を知らせる予兆SE
- スコアに応じた主人公のリザルト表情切り替え
- 犬以外の被写体をランダム出現させ、プレイごとの撮影機会を変化させる

### Could

MustとShouldの完成後、時間に余裕がある場合だけ実装する機能。

- 難易度選択
- 3ステージで3枚撮影し、写真ごとの結果と合計結果を表示する本編フロー
- レア被写体の追加
- スコアに応じた収入
- アクセサリーの購入と装着
- アクセサリーが写真に写った場合の効果
- unityroomのスコアボードへのいいねスコア送信（ゲーム内にランキング一覧を表示するUIは作らず、
  unityroom側のゲームページで見る前提。詳細は`ADR-0017`を参照）

収入、ショップ、アクセサリーは相互に依存するため、一部だけを先行実装しない。

### Won't

今回の公開版では実装しない。

- 実在SNSとの連携
- 実在SNSのロゴや画面の複写
- 写真フィルターや画像加工機能

## エッジケース

実装前に期待動作を決め、テストまたはPlay Modeで確認する。

- 制限時間とシャッター入力が同じフレームに発生した場合
- 制限時間内に撮影しなかった場合
- シャッターを連打した場合
- 写真枠内に対象が1つもない場合
- 同じ種類の対象が複数写った場合
- 加点対象と減点対象が同時に写った場合
- 合計点が0または負になった場合
- 基準点が写真枠の境界上にある場合
- 撮影と対象の生成・退場が同じフレームに発生した場合
- SNS表示やシーン遷移中に入力した場合
- リトライ後に前回の写真、スコア、タイマーが残らないこと
- 必須のInspector参照が未設定の場合
- `Time.timeScale`を変更する演出を採用した場合のタイマー動作
- ランダムピンボケが重複した場合の表示強度と0点判定
- ピンボケの開始から1.0秒・2.0秒ちょうどに撮影した場合
- 10秒終了直前のピンボケとResult遷移が重なった場合
- 通常の0点、負の計算結果を0表示した場合、ピンボケによる強制0点で、いいね演出を再生せず弾幕コメントだけが流れること
- 0点リザルト演出の開始前・開始後にスキップしても、弾幕演出の停止とシーン遷移が従来どおり行えること
