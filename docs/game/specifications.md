# Game Specifications

## 状態

2026年7月27日の仕様検討結果を反映済み・一部未決定。

この文書では、実装者とレビュアーが「仕様か不具合か」を判断できる粒度で記載します。
未決定の項目は推測で埋めず、`未決定`と記載します。

状態の意味:

- `確定`: 企画メモで明示され、MVPの前提として扱う
- `草案`: 企画メモに案として記載されているが、実装前の合意が必要
- `未決定`: 実装方法または期待動作を決める必要がある

`確定`、`草案`、`未決定`は仕様の確定度を表す。
機能の実装優先度は、後述するMoSCoW分類で管理する。

## 一文で説明

動く被写体をタイミングよく自撮り写真へ収め、架空のSNSで多くの「いいね」を
獲得する2Dスコアゲーム。

## コア体験

10秒間に背景を横切る被写体の予兆と動きを見て、加点対象を写真へ収め、
減点対象を避けるタイミング判断を楽しむ。

## ゲーム進行

MVPのゲーム進行:

```text
タイトル
→ 撮影開始メッセージ
→ 10秒間の写真撮影
├─ 10秒以内に撮影できた
│  → カウントダウン終了
│  → 架空SNSへの投稿演出
│  → リザルト
│  → タイトルへ戻る
└─ 撮影できずに時間切れ
   → ゲームオーバー
```

- MVPでは1ステージにつき写真を1枚だけ撮影し、その写真のリザルトを表示する。
- 本編案では3ステージで3枚撮影する。各ステージで「10秒間の写真撮影、
  カウントダウン終了、架空SNSへの投稿演出」を順に行い、投稿演出の終了後は
  次のステージの撮影を開始する。最後のステージの投稿演出後に、写真ごとの結果を
  順番に表示し、最後に合計リザルトを表示する。ただし、3ステージ化はMVPに含めない。
- 難易度選択はCouldとし、Mustのみで完成させる場合は省略する。
- Title、SNS、Resultは別シーンとする。Gameはステージごとに別シーンを作成できる構成とし、MVPでは1つのGameシーンだけを使用する。
- MVPのGameOverは、Gameシーン内のUIとして表示する。

本編案（Could）のゲーム進行:

```text
タイトル
→ ステージ1: 撮影開始メッセージ → 10秒間の写真撮影 → カウントダウン終了 → SNS投稿演出
→ ステージ2: 撮影開始メッセージ → 10秒間の写真撮影 → カウントダウン終了 → SNS投稿演出
→ ステージ3: 撮影開始メッセージ → 10秒間の写真撮影 → カウントダウン終了 → SNS投稿演出
→ 写真ごとのリザルトを順番に表示
→ 合計リザルト
→ タイトルへ戻る
```

### 開始

1. タイトルを表示する。
2. GUIボタンのクリック、Spaceキー、またはEnterキーでゲームを開始する。
3. 難易度選択を採用する場合は、選択後に最初のステージを開始する。

タイトルの具体的なレイアウトは未決定。

### 撮影

1. 撮影場所を示すメッセージを表示する。
2. 撮影可能時間を10秒間とする。
3. 撮影中、得点対象または減点対象のオブジェクトが背景を移動する。
4. プレイヤーは1回だけシャッターを切れる。
5. シャッター時点で写真枠内にいる対象を記録する。
6. 撮影後も10秒のカウントダウン終了までタイマーと被写体を動かし続ける。
7. 10秒以内に撮影できなかった場合はゲームオーバーとする。
8. 撮影できた場合は、カウントダウン終了後に約2秒のSNS投稿演出を自動再生する。

### 終了

MVPではSNS投稿演出後、撮影した1枚の写真、いいね数、コメント、主人公の表情を
リザルトに表示する。

本編案では写真ごとの結果を操作で順番に表示し、全写真の表示後に合計値を表示する。
主人公の表情は良い・普通・悪いの3段階とするが、境界値はプレイ確認後に決める。

### リトライ

リザルト後はタイトルへ戻る。
ゲームオーバー後の遷移と、リザルトから直接リトライできるようにするかは未決定。

## 操作

| 操作 | 入力                                    | 挙動 | 状態 |
|---|-----------------------------------------|---|---|
| 難易度選択 | GUIボタンのクリック、Space、Enter | 難易度を選ぶ | 機能自体がCould |
| シャッター | GUIボタンのクリック、Space、Enter | 現在の写真枠を1回だけ撮影する | 確定 |
| 次へ進む | GUIボタンのクリック、Space、Enter | リザルトなどから次の状態へ進む | 確定 |
| カメラ・写真枠の移動 | MVPではなし | MVPでは固定する。MVP後はUIに隠れない範囲で移動可能にする | MVP後の入力と移動量は未決定 |
| キャンセル | Escを第一候補、Qを代替候補 | キャンセル可能な状態を閉じる | 入力の最終決定が必要 |

MVPではPCのキーボード・マウス操作を必須対応とする。タッチ操作は余裕がある場合に
追加する。入力には、現在プロジェクトで有効なInput Systemを使用する。

## 撮影判定

### 判定方法

各得点対象オブジェクトには、写真へ写ったかを判定する判断ポイントを1つ設定する。
判断ポイントは被写体の子に置く空のGameObject（`Transform`）とする。
撮影時点で判断ポイントが写真枠内にあり、かつ判断ポイントが他の描画物に隠れて
いなければ、そのオブジェクトを撮影対象として記録する。

例として、猫は顔の位置を基準点にする。

- 基準点が枠線上にある場合は枠内として扱わない。
- 他の描画物により判断ポイントが隠れている対象は、写真枠内でも撮影対象として扱わない。
- MVPでは1ステージにつき撮影は1回だけなので、同じオブジェクトの重複撮影は発生しない。

非表示・退場中の判定方法と、描画順・Collider・Raycastのどれで「判断ポイントが
隠れている」ことを実装するかは未決定。実装方式は、写真用Cameraから見た結果と
一致することを受け入れ条件とする。

### 写真データ

撮影画像には`RenderTexture`と`Texture2D`を使用する。

1. 撮影用Cameraの出力先を`RenderTexture`にする。
2. 撮影中は`RenderTexture`をプレビューとして表示する。
3. シャッター時に`RenderTexture`の内容を`Texture2D`へコピーする。
4. `Texture2D`に、撮影対象の種類と個数を関連付けて保持する。
5. SNS画面とリザルトでは、保持した`Texture2D`をUIの`RawImage`へ表示する。

画面全体を撮影する`ScreenCapture`は使用せず、カメラUIを撮影画像に含めない。
再撮影やリトライで不要になった`Texture2D`は破棄し、プレイを繰り返したときに
画像データがメモリへ残り続けないようにする。

## スコア

- 写真は固定値1,000いいねから開始する。
- 写真に写った対象の種類と個数から加減点を計算する。
- 加減点といいね数の変換比率は1:1とする。
- 計算結果が0以下の場合、表示するいいね数は0とする。
- MVPは写真1枚なので、その写真のいいね数を最終結果とする。
- コメントは演出だけに使用し、スコアへ影響させない。

```text
加減点 = Σ（写った対象の個数 × 対象ごとの点数）
写真のいいね数 = max(0, 1,000 + 加減点)
```

内部の加減点が負になることは許可するが、プレイヤーへ表示するいいね数は負にしない。
本編案の3枚分を合算する方法は、3ステージ化へ着手する前に決める。

## 被写体・障害物

すべて2Dで表現する。奥行きは、オブジェクトごとに設定したスケールと移動速度で
遠近感を表現し、登場後は原則としてそのスケールと速度を維持して横切る。

MVP候補のうち、採用と点数が確定している対象:

| 対象 | 点数 | 予兆・特徴 | 状態 |
|---|---:|---|---|
| 犬 | +500 | 10秒間の決められた時刻と速度で出現する | 確定 |
| 汚れた服の人 | -600 | 音が鳴り、移動が遅い | 確定 |
| 狂犬 | -800 | 吠える音 | 確定 |
| ビニール袋 | -100 | 強風や音。複数出現する場合がある | 確定 |
| 鳥 | +800 | 未決定 | 確定 |
| スズメ | +5 | 未決定 | 確定 |

桃は+4,000いいねの被写体候補であり、川がある本編ステージだけに出現する。MVPには含めない。

猫、孔雀・青い鳥、手ぶれ、川のゴミなど、上表にない企画候補はMVP外とする。

## 難易度

難易度選択はCouldとし、Mustの完成後に時間がある場合だけ実装する。

実装する場合の難易度数と、出現対象、速度、予兆、制限時間、スコアのうち
何を変化させるかは未決定。

## ゲームクリア・ゲームオーバー条件

- 10秒以内に1枚も撮影できなかった場合はゲームオーバーとする。
- 10秒以内に撮影できれば、いいね数にかかわらずリザルトへ進む。
- スコアによるゲームオーバーは設けず、ゲームを完了した後はスコアアタックとして扱う。
- GameOverを別シーンにするか、Gameシーン内のUIにするかは未決定。

## UI

### タイトル

- タイトルを表示する。
- ゲーム開始の導線を表示する。
- 難易度選択を採用する場合は、その導線を表示する。

具体的なレイアウトと入力案内は未決定。

### 撮影中

- スマートフォンのカメラを想起させる、簡素なオリジナルUIを使用する。
- 写真枠を表示する。
- 被写体はGameシーンの画面全体を移動できる。写真枠はUIを除いた一部の領域に置く。
- MVPでは写真枠を固定する。MVP後に移動を追加する場合は、UIに隠れない領域だけを
  写真枠の移動可能範囲とする。
- 残り時間をプレイヤーが確認できるようにする。
- シャッター操作を表示する。

残り時間の表示形式と、撮影済み対象の得点を撮影中に見せるかは未決定。

### SNS表示

- 実在サービスのロゴや画面を複写せず、架空SNSのオリジナルUIとする。
- 10秒以内に撮影できた場合、カウントダウン終了後に約2秒の投稿演出を自動再生する。
- 投稿演出の終了後、自動的にリザルトへ進む。
- 「いいね」とコメントが増える演出はShouldとする。

コメントの文面、件数、対象別の対応は未決定。

### リザルト

- MVPでは撮影した1枚の写真、いいね数、コメントを表示する。
- MVPでは主人公の表情を表示する。
- タイトルへ戻る導線を表示する。

Shouldでは良い・普通・悪いの3段階へ切り替える。境界値は、実際にプレイして
バランスを確認した後に決める。
本編案では、写真ごとの結果をクリックで順番に表示し、最後に合計値を表示する。

## シーン

必要最小限のシーン数とし、機能は可能な範囲でPrefabへ分離する。

| 画面状態 | 用途 | シーン分割 |
|---|---|---|
| Title | タイトル・開始 | 分割する |
| Difficulty | 難易度選択 | 機能自体がCould |
| Game | 撮影 | ステージごとに分割可能。MVPでは1シーン |
| SNS | 投稿演出 | 分割する |
| Result | 写真・いいね・コメント表示 | 分割する |
| GameOver | 未撮影による失敗表示 | MVPではGame内UI |

Bootstrapは導入しない。
写真、スコア、進行状態はデータを渡す側が受け渡し処理を実装する。ただし、具体的な
データ契約、null可否、破棄タイミング、受け渡し失敗時の挙動は実装前に合意する。

詳細は`docs/decisions/ADR-0011-scene-and-bootstrap-policy.md`を参照する。

## MoSCoW

この分類は、2026年8月2日の公開版に対する実装優先度を表す。
まずMustだけでゲームを1周遊べる状態にし、完成を確認してからShould、Couldの順に着手する。

### Must

ゲームとして成立し、公開可能な最小範囲。
1つでも未完成ならShouldとCouldへ着手しない。

- タイトルからゲームを開始できる
- 撮影場所を示すメッセージを表示できる
- 10秒間、被写体が背景を移動する
- `RenderTexture`から`Texture2D`へ写真を撮影できる
- 写真枠内の対象と個数を判定できる
- 対象と個数からスコアを計算できる
- 撮影結果を保持し、SNS表示で確認できる
- 「いいね」とコメントを表示できる
- 10秒以内に未撮影の場合、ゲームオーバーを表示できる
- SNS投稿演出後に1枚分のリザルトを表示できる
- タイトルへ戻り、もう一度プレイできる
- 進行に必要な最低限のボタンUIがある
- 主人公、得点対象、カメラ、SNS、リザルトに最低限必要な画像がある

### Should

なくてもゲームは成立するが、撮影結果の理解しやすさや手応えを高める機能。

- シャッターを切ったときの演出
- 「いいね」とコメントが増える演出
- 加点または減点対象の出現を知らせる予兆SE
- スコアに応じた主人公のリザルト表情切り替え

### Could

MustとShouldの完成後、時間に余裕がある場合だけ実装する機能。

- 難易度選択
- 3ステージで3枚撮影し、写真ごとの結果と合計結果を表示する本編フロー
- ランダム出現またはレア被写体の追加
- スコアに応じた収入
- アクセサリーの購入と装着
- アクセサリーが写真に写った場合の効果

収入、ショップ、アクセサリーは相互に依存するため、一部だけを先行実装しない。

### Won't

今回の公開版では実装しない。

- 実在SNSとの連携
- オンラインランキング
- 実在SNSのロゴや画面の複写
- 写真フィルターや画像加工機能

## エッジケース

実装前に期待動作を決め、テストまたはPlay Modeで確認する。

- 制限時間とシャッター入力が同じフレームに発生した場合
- 制限時間内に撮影しなかった場合
- シャッターを連打した場合
- 写真枠内に対象が1つもない場合
- 同じ種類の対象が複数写った場合
- 加点対象と減点対象が同時に写った場合
- 合計点が0または負になった場合
- 基準点が写真枠の境界上にある場合
- 撮影と対象の生成・退場が同じフレームに発生した場合
- SNS表示やシーン遷移中に入力した場合
- リトライ後に前回の写真、スコア、タイマーが残らないこと
- 必須のInspector参照が未設定の場合
- `Time.timeScale`を変更する演出を採用した場合のタイマー動作
