# ADR-0018: ランダムピンボケに既存UIブラーを再利用する

## 状態

採用

## 日付

2026-08-09

## 決定

- `Playing`中の10秒を0.5秒単位で独立抽選し、少なくとも1回発生する確率を約20%にする。
- 当選時刻は当選区間内でランダム化し、1ゲーム中の複数回発生と3秒演出の重複を許可する。
- 既存の`Stage/PhotoPreviewBlur`シェーダと実行時Materialを再利用し、重複時は各演出の最大強度を表示する。
- ぼかしは開始から1.5秒まで強くし、3秒まで解除する。開始から1.0秒以上2.0秒以下に
  撮影した写真は、被写体判定にかかわらずスコアを0へ強制する。
- シャッター時は同じシェーダでPhotoCamera出力を一時RenderTextureへBlitしてから保存する。
  これにより、保存写真にはぼかしを残しつつ、カメラUIは含めない。
- 強制0点フラグは`CapturedPhoto`から`ResultData`へ渡し、Result Featureで最終スコアを0とする。
  被写体別明細は表示せず、`ピンボケ`の0点だけを表示する。
- ランダムピンボケがすべて解消したときは、ゲーム開始時に使う既存の`Scene_SE_Manager`を
  呼び出し、同じ解消SE（既存設定のSE番号17・音量0.4）を再生する。
- 10秒終了後の既存Result遷移は待たせず、終了間際のぼかしはシーン破棄時に打ち切る。

## 理由

開始時のピント合わせと同じシェーダ・Material管理を使うことで、4:3プレビューだけをぼかす既存の
UI範囲を保つ。保存画像のぼかしはPhotoCamera出力にだけ適用するため、UIを焼き込まずに撮影時の
見た目とResult写真を一致させられる。

## 影響

- ADR-0015の「保存画像へぼかしを焼き込まない」方針は、開始時ピント合わせにのみ残る。
- ランダムピンボケの撮影時だけ、PhotoCamera出力を一時RenderTextureへBlitする。
- 新規外部ライブラリ、追加Camera、追加RenderTexture資産は導入しない。

## リザルト演出

ピンボケによる強制0点は通常の0いいねと同じリザルト演出にする。弾幕コメントのみを流し、ハート、
いいね増加SE、投稿パネルのバウンドは再生しない。代わりにGame_Stage1のゲームオーバーSEを1回再生する。
