# Unity 1week ミーティングパック

3人チーム、7日間、1人あたり約3時間/日の開発を想定した、アジェンダ兼議事録です。

## 方針

- 各日は原則1回、必要な日だけ2回のミーティングにしています。
- すべての会議ファイルは `00_templates/meeting_template.md` を元にしています。
- 会議ごとに、明らかに不要な見出しだけを削除しています。
- 見出し番号と項目名をできるだけ統一し、人間だけでなくAIも横断的に読み取りやすくしています。
- 1つのファイルを、会議前はアジェンダ、会議中・会議後は議事録として使用します。

## ミーティング構成

| Day | ミーティング | 推奨時間 |
|---|---|---:|
| Day 1 | 企画決定会 | 60分 |
| Day 1 | プロトタイプレビュー | 25分 |
| Day 2 | Vertical Slice計画・統合会 | 20分 |
| Day 2 | Vertical Sliceレビュー | 20分 |
| Day 3 | MVP完成判定会 | 30分 |
| Day 4 | ゲームプレイ改善会 | 35分 |
| Day 5 | ポリッシュ・機能凍結会 | 30分 |
| Day 6 | テスト・バグトリアージ会 | 30分 |
| Day 6 | リリース候補判定会 | 20分 |
| Day 7 | リリース判定・公開会 | 30分 |
| Day 7 | 公開確認・振り返り会 | 30分 |

## 使い方

1. 会議前に対象ファイルを開き、日時・参加者・関連Issueを記入します。
2. アジェンダの時間配分に沿って進行します。
3. 議論中は「確認した事実」「意見・選択肢」「判断理由」「結論」を分けて記録します。
4. 会議終了時に、決定事項、アクションアイテム、未解決事項を確定します。
5. 作業範囲を決める会議では、Scene・Prefab・Scriptの担当を明記します。

## AIで読み取る際のポイント

各ファイルで以下の見出しを共通化しています。

- `## 2. 目的`
- `## 3. 終了条件`
- `## 5. アジェンダ`
- `## 7. 議論メモ`
- `## 8. 決定事項`
- `## 10. アクションアイテム`
- `## 14. 未解決事項・リスク`
- `## 15. 次回確認事項`

特定の情報を抽出するときは、見出し名を指定すると安定します。
